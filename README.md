# 七国纵横 · Diplomacy Web

标准七国《外交》（Diplomacy）的网页版。一条命令起服务，浏览器里打完整局。

> **当前阶段**：单局多人 + 模型入座。房主在「管理」页生成 7 条座位链接，一人一条发出去，
> 各自只看得到自己那国的私信；也可以把几个座位勾给大模型，人和模型混打一局。
> 规则、结算、私信保密、命令校验全部走真裁判。

**English TL;DR** — A self-hosted web version of standard 7-player Diplomacy. Docker one-liner,
single match, hot-seat plus LLM seats over any OpenAI-compatible endpoint, real referee
(private messaging, simultaneous adjudication, order validation). Multi-room is on the roadmap.

## 快速开始

### Docker

```bash
docker run -d --name diplomacy -p 8080:8080 -v "$PWD/data:/data" \
  ghcr.io/dc1024/diplomacy-web:latest
```

打开 <http://localhost:8080>。

镜像标签跟随 git tag 但**不带 `v` 前缀**：git tag `v0.4.0` → 镜像 `0.4.0`、`0.4`、`latest`。
要固定版本就写 `:0.4.0`，别写 `:v0.4.0`（那会 404）。

数据目录有两种挂法，都支持：

| 挂法 | 命令 | 说明 |
|---|---|---|
| 绑定挂载 | `-v "$PWD/data:/data"` | 宿主目录属主随意，容器启动时自动改成 `10001` |
| 命名卷 | `-v diplomacy-data:/data` | 归属由镜像带入，无需处理 |

容器以 root 启动、修正 `/data` 属主后**立即降权到 uid 10001** 运行进程。不想要这一步就加
`--user 10001:10001`（此时宿主目录必须已经属于 10001）。

### Docker Compose

```bash
docker compose up -d
```

### 本地运行（Python 3.12）

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt     # Windows: .venv\Scripts\pip
.venv/bin/python -m app.main                  # Windows: .venv\Scripts\python
```

打开 <http://localhost:8080>。数据写在 `./data/state.json`，可以用 `DATA_DIR` 改位置。

## 怎么玩

1. 页面打开即自动开一局，`1901 年春` 开始。
2. 左侧点一个国家切换视角——**热座模式下你持有全部 7 个座位令牌**，能看到该国全部的私信。
3. 「简报」页是这个国家当前能看到的一切：局面、别人发来的信、本阶段要做什么、其他几家交了几份令。
4. 「发信」页发私信（300 字）或公开发言（400 字）。承诺没有强制力，允许欺骗。
5. 「军令」页每行一条命令，提交整份。格式不对会返回该部队的合法选项。
6. 所有需要行动的国家都交令后自动结算，进入下一阶段。

命令写法：

```text
A PAR - BUR            陆军移动
A MAR S A PAR - BUR    支援移动
F ENG C A LON - BRE    海运（陆军写 A LON - BRE VIA）
A PAR H                驻守
A BUR R PAR            撤退
A PAR B                增兵
```

完整规则见页面简报，或上游的 `workspace/RULES.md`。

> **未下令的部队不会自动驻守**——每支需要行动的部队都必须下令。这是原版规则，不是 bug。

### 日夜模式

页头右上角那个按钮就是开关：写着「☀ 日间」表示点一下切到日间，写着「☾ 夜间」表示点一下
切到夜间。**第一次打开跟随系统设置**（`prefers-color-scheme`），你手动点过之后就以浏览器
本地记录为准（`localStorage` 的 `dw_theme`），刷新、换页都不会跳回去；换浏览器或清缓存才会
重新跟随系统。

不需要配置、不落服务端，也不影响对局。夜间是默认的深色；日间把底色翻成浅灰白、正文压深、
强调色从亮金压到深金（金色按钮保持原样），地图同时换一套取色——海是浅蓝、陆地浅灰，
因为地图是 SVG 内联填充而不是 CSS，切主题时前端会**重画一遍**。

### 想几个人一起玩

设了 `ADMIN_KEY` 之后，右侧「管理」页 → **生成 7 条座位链接**，每个国家一条。把每条单独发给
对应的玩家（**别群发**——链接里就带着该国令牌）。

对方打开链接后：

- 地址栏里的令牌会被立刻抹掉，不会留在截图或历史记录里；
- 只剩「简报 / 发信 / 军令 / 收件箱」四个页签，左侧其余六个座位是锁死的，切不过去；
- 看不到「新局」按钮，也没有管理面和模型页。

刷新页面仍是同一国（绑定记在浏览器本地）；想换回房主视角点右上角「退出绑定」。

一个人自己玩就还是热座：不设 `ADMIN_KEY`，打开页面即拿全部令牌，点左侧国家切换视角。

### 有人挂机怎么办

设 `PHASE_SECONDS` 打开阶段时钟，当前阶段倒计时到 0 时，还没交令的国家按**驻守**处理，然后
立即结算——不会让六个人等一个人。

```bash
docker run -d -p 8080:8080 -e ADMIN_KEY=... -e PHASE_SECONDS=300 \
  -v "$PWD/data:/data" ghcr.io/dc1024/diplomacy-web:latest
```

到点托管不是踢人：人回来还能接着打，只是这一阶段被按了驻守。管理面还有「暂停 / 继续」
（暂停时时钟停走、交令也不结算）和「强制结算」（立刻把没交令的国家按驻守处理并推进）。
不设 `PHASE_SECONDS`（默认 0）就一直等，适合一个人慢慢想。

## 让模型入座

「模型」标签页里勾选国家即可，勾上就由模型接管，取消就收回人类。模型每回合只看到
**最近 3 段结算 + 最近 30 条消息 + 局面**，更早的历史压成一行摘要——这是成本能收住的关键。
输出不是合法 JSON 或者命令不合法会自动修一次，仍不行就降级为合法驻守，不会卡住对局。

### 在网页里填配置（推荐）

不用改环境变量、不用重启容器。进「模型」页签，展开顶上的**接入设置**：

| 字段 | 填什么 |
|---|---|
| 接入方式 | `OpenAI 兼容`（默认）或 `离线脚本`（不联网、不花钱，用来走通流程） |
| Base URL | 要写到 `/v1`，例如 `https://api.deepseek.com/v1`。误贴 `/chat/completions` 会被自动去掉 |
| 模型名 | 供应商那边的 ID，例如 `deepseek-chat`、`qwen-plus`、`gpt-4o-mini` |
| API Key | 存过之后只显示尾四位；**留空表示沿用已保存的那把**，不会把密钥清空 |
| 预算 / 单价 | ¥/局 与 ¥/百万 token。按你实际供应商的价改，否则花费是估的 |
| 输出上限 | 单次回复的 token 上限，**含思维链**。默认 4096。推理型模型别往下调 |
| 上下文 | 保留几段结算、几条消息。调大更连贯，也更贵 |

三个按钮：「保存」「测试连接」「保存并测试」。「测试连接」会真发一次很小请求，把
**地址写错 / 模型名不对 / 密钥无效**分成三种不同的报错——这三种在页面上本来都只表现为
「勾了座位但不动」。测试不会覆盖已保存的配置。

「输出上限」这个字段看着多余，其实是最容易踩的坑：`max_tokens` 是**含思维链**的总配额。
推理型模型（deepseek-r1、很多网关的 smart-split 路由）会先烧一两千 token 想，配额给小了
`content` 回来就是空串，页面只会说「模型连续两次未给出可解析的 JSON」——像模型不会写 JSON，
其实是没地方写。实测同一条提示词的思维链在 2200–3900 之间浮动，所以默认给 4096，撞墙后按
**三级阶梯**自救：

1. 撞墙 → 把配额放宽一倍再试（够不着是「地方不够」）；
2. 还撞墙 → 说明它在**一直想**（实测有座位把 6000 token 全用来想、正文一个字没有），
   这一级改成加一句「不要再推理，直接给出 JSON 答案」，配额同时收回到 2000；
3. 三级都不行 → 降级为合法驻守，不让一桌人陪它等。

三次尝试**每一次都计费**——成本数字里看得见，页面上也看得见「降级」计数。

**别把配额往上调**，这条是实测出来的反直觉结论。同一模型（deepseek-v4.1-flash）各跑
8 阶段：

| 输出上限 | 花费 | token | 调用次数 | 时长 |
|---|---|---|---|---|
| 4096 | **¥2.8935** | 458 388 | 77 | 46 分钟 |
| 8192 | ¥3.7449 | 551 629 | 62 | 53 分钟 |

配额翻倍确实让调用次数少了 22%，但**总 token 涨了 20%**：这条路由的思维链是长尾，
约三成调用连 8192 都填不满。配额抬高并不能让它们一次说完，只是把「撞墙时白烧的那一次」
从 4096 变成 8192（撞墙后还要再给 16384）。**配额只决定撞墙时烧多少，不决定撞不撞墙**，
所以给到分布中位数附近最省。


保存即生效：正在跑的座位立刻换用新 provider，不用重启。因为预算调高而此前撞线停掉的座位
会自动放回来。

配置存在 `data/llm.json`（跟 `DATA_DIR` 走），权限 `0600`，**里面是明文密钥**：别提交进仓库、
别整目录打包发人。`.gitignore` 已挡掉 `data/`。优先级是 `data/llm.json` > 环境变量 > 未配置，
所以下面这套 `LLM_*` 环境变量只是**首次启动的默认值**：

```bash
docker run -d -p 8080:8080 \
  -e LLM_BASE_URL=https://api.deepseek.com/v1 \
  -e LLM_API_KEY=sk-... \
  -e LLM_MODEL=deepseek-chat \
  -v "$PWD/data:/data" ghcr.io/dc1024/diplomacy-web:latest
```

没有任何 API key 也想跑一遍流程？在表单里把「接入方式」选成**离线脚本**（等价于
`LLM_PROVIDER=scripted`），内置脚本座位会代替模型，用来验证前端与结算链路，不产生费用。
`GET /api/llm/settings` 的 `source` 会告诉你当前用的是哪一层：`file` / `env` / `none`。

## 架构

```text
浏览器（单页，无构建步骤）
   │  X-Seat-Token
   ▼
FastAPI（app/main.py，薄壳：路由 + 鉴权 + 结算触发）
   │
   ▼
Arena（app/engine/arena.py，vendored）
   ├─ 鉴权、私信过滤、命令校验、幂等、回滚
   └─ diplomacy 1.1.2（结算引擎）
        └─ data/state.json（全量存档）
```

裁判内核来自 [meow-ai-arena](https://github.com/chen-006/meow-ai-arena) 的第 4 集，
是经过三局 105 阶段实战验证的实现。本仓库只加了 HTTP 壳和前端，没有改业务逻辑——
改动清单与升级方式见 [`app/engine/VENDOR.md`](app/engine/VENDOR.md)。

**必须单 worker**：`Arena` 是进程内单例，多 worker 会各自持有一份状态。`Dockerfile` 已固定。

**实时更新怎么走**：前端开一条 `GET /api/events`（SSE）。服务端用内核的 `admin_wait()`
等 `bump()`，任何人交令、结算、暂停都会立刻推一份 `summary()` 快照——里面**没有任何座位
令牌**，它只是「该刷新了」的信号，简报与私信仍走带令牌的 `/api/brief`、`/api/inbox`。
推送断开时浏览器自动重连，同时退回 5 秒轮询，页头会从「实时」变回「轮询」。
放在 nginx 后面要允许 `text/event-stream`（已发 `X-Accel-Buffering: no` 关掉缓冲）。

**复盘为什么不会串国**：`GET /api/replay` 不接收 `?power=`，只认 `X-Seat-Token`（管理员想
看某国，就拿那条座位令牌——建局响应与 `/api/links` 里都有）。每个阶段取两块——
`history_text(power, phase)` 的结算原文、`inbox(power, phase)` 的往来信件——两个方法本身都按
座位过滤，所以「德国写给法国的信」在意大利的复盘里不存在。一局 55 个阶段一次返回仍是小请求，
暂不做分页与缓存。

**配置为什么能改完就生效**：`app/llm/settings.py` 把「地址 / 模型名 / 密钥 / 预算 / 单价 /
上下文」收成一个 frozen dataclass，`current()` **每次现读** `data/llm.json`，不缓存。`PUT` 之后
遍历在册座位逐个 `apply_to(seat)`：换 provider、回填价格与预算、并把因超额停掉的座位放回来。
`public()` 用 `asdict` 之后 `pop("api_key")`，所以「不回传密钥」是结构上做到，而不是靠人记得删。
密钥写盘走 `mkstemp` + `chmod 0600` + `os.replace` 原子替换，半途断电不会留下半个文件。

**地图从哪来**：不自己描图。引擎 wheel 里本来就带一份 `diplomacy/maps/svg/standard.svg`
（jDip Detailed Standard Map，GPL），`app/map_data.py` 直接把它解析成 76 块轮廓 + 地名锚点，
启动后第一次请求解一次（约 0.3 秒）并缓存。绕开两个坑：图上五片海用的是 jDip 缩写
（`GOL/MID/NAT/NRG/TYN`），引擎叫 `LYO/MAO/NAO/NWG/TYS`；文件声明的 `viewBox="0 0 1835 1360"`
和实际图形对不上（真实包围盒到 `2023×1527`），照声明取景会把突尼斯和那不勒斯切掉，所以取景
按内容包围盒算。

`GET /api/map` 匿名、`Cache-Control: public, max-age=86400` 且带 `ETag`（内容哈希）——几何真
变了（换了地图文件）浏览器下次问一句就拿到新的，不用叫用户清缓存。`GET /api/board` 给部队与
中心归属：这两样在 Diplomacy 里是**公开信息**，所以不按座位过滤；唯一私密的是 `mine`，只含
调用者座位的合法命令。注意口径——`mine` 的键是**基础地名**（`STP`），命令串里才带海岸
（`F STP/SC - BOT`），前端拿基础名点图、拿整串下命令。

## 配置

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `DATA_DIR` | `./data` | 存档目录（Docker 里是 `/data`） |
| `ADMIN_KEY` | 空 | 管理员密钥。**留空时建局/清档不鉴权，只适合本机单人** |
| `HOST` | `0.0.0.0` | 监听地址。设 `127.0.0.1` 表示只听本机 |
| `PORT` | `8080` | 端口 |
| `LOG_LEVEL` | `info` | 日志级别 |
| `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` | 空 | **只作默认值**：网页保存过配置（`data/llm.json`）后以文件为准 |
| `LLM_PROVIDER` | — | 填 `scripted` 用内置脚本座位，离线演练不花钱（网页里也能选） |
| `LLM_BUDGET_CNY` | `20` | 单个座位的预算上限，撞线即停并降级为驻守 |
| `LLM_PRICE_IN` / `LLM_PRICE_OUT` | `2` / `8` | 估价用单价（¥/百万 token），按供应商实际价格改 |
| `LLM_KEEP_HIST` / `LLM_KEEP_MSGS` | `3` / `30` | 上下文窗口：保留几段结算、几条消息 |
| `LLM_INTERVAL` | `2` | 后台推进模型的轮询间隔（秒） |
| `PHASE_SECONDS` | `0` | 每阶段限时（秒）。`0` = 不限时；到点把没交令的国家按驻守处理并结算 |

### 关于 `ADMIN_KEY`（对外部署必读）

`POST /api/match` 会一次性返回全部 7 个座位令牌——热座模式下这是便利，**挂到公网就等于
把全场私信公开**。因此：

- 本机自己玩：留空，打开页面即开局。
- 给别人访问：必须设 `ADMIN_KEY`。设置后建局与清档需要密钥，页面右上角会出现输入框。

```bash
docker run -d -p 8080:8080 -e ADMIN_KEY="$(openssl rand -hex 16)" \
  -v "$PWD/data:/data" ghcr.io/dc1024/diplomacy-web:latest
```

`GET /healthz` 里的 `admin_required` 反映当前是否为受保护状态，`exposed` 反映监听是否超出本机。
**两个条件同时踩到（没密钥 + 对外监听）时页面顶部会挂一条红色告警**，直接说明令牌会被谁拿走。
告警可以收起，状态记在浏览器本地；它只是提示，不是拦截——真要对公网开就得设密钥。

## 开发

```bash
pip install -r requirements-dev.txt
ruff check .
pytest -q
```

测试盯着八件最容易坏的事：令牌鉴权与令牌隔离（`?power=` 改不了视角）、私信隔离（含**复盘**
里也不许出现别国信件）、结算门控、模型上下文窗口、模型谈判记忆（自己发出的信必须回到它自己
的上下文里）、掉线托管（座位抛异常也必须有令可结）、实时推送（连上即给快照、动一次推一次、
载荷不许出现令牌）、复盘阶段对齐（结算过的阶段一条不少，且指向的阶段是下一个而非刚结算的那个）。
地图另有五条：76 块与引擎基础地点一一对应、图上五片海的旧名要做别名、`/api/map` 匿名且可缓存、
`/api/board` 部队公开但命令只给自己、以及「从图上点出来的令必须被引擎接受」。
模型配置另有十二条，重点不是「能存」，而是**密钥不会漏**：GET / PUT / `/api/llm` 三处响应、
错误文本、日志里都不许出现明文；空密钥等于沿用旧值而不是清空；漏传的字段不能被盖成空；
只有管理员能动；文件读坏了要退回环境变量而不是 500；保存后已入座的座位要换上新的 provider，
且因预算撞线停掉的座位在预算调高后要活过来。
其中整局回归让 7 个脚本座位把 1901 打到终局，任何一环退化都会立刻红。

CI 在每次 push 时跑 lint + 测试 + 构建镜像 + 容器冒烟（含绑定挂载权限、管理密钥、座位链接、
SSE 首帧、模型座位、阶段时钟自动结算、**网页改模型配置后不重启即生效**，以及**镜像里那份
SVG 能不能解析出 76 块**——本地跑通不代表镜像里有）。推 `v*` 标签会构建 `linux/amd64` 与
`linux/arm64` 双架构镜像并推到 GHCR。
